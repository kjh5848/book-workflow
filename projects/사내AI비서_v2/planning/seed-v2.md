# 씨앗 v2

> v1에 **형식 표준** 섹션을 추가한 버전. 본문(주제·동기·의도·차별점)은 v1과 동일.

## 주제
RAG 기반 사내 AI 비서 만들기 — LLM + 벡터DB + FastAPI로 사내 문서 검색 AI 구축

## 집필 동기
기존 RAG 관련 자료는 대부분 이론 설명이나 조각난 예제에 머문다. "Retriever가 뭔지"는 알겠는데, 실제로 사내 문서를 넣고 질문하면 어떻게 되는지, 정확도가 안 나올 때 뭘 건드려야 하는지를 보여주는 자료는 드물다. 이 책은 LLM 환각을 직접 체험하는 것에서 시작해서, 문서를 파싱하고, 벡터화하고, RAG 엔진을 만들고, 에이전트로 통합하고, 성능을 튜닝하는 전 과정을 하나의 프로젝트로 연결한다.

## 저자 경험
> AI가 범용적으로 작성 — 특정 저자의 경험을 전제하지 않음.

이 기술을 처음 접하는 사람이 겪는 전형적 경험으로 서술한다.

## 핵심 메시지
"직접 만들어봐야 이해한다" — 이론 100번 읽는 것보다 환각을 한 번 보고, 코드를 한 번 짜고, 튜닝을 한 번 돌려보는 게 낫다.

## 책의 의도
**이해 중심의 스토리텔링**으로 RAG 전체 파이프라인을 설명한다. CH01~CH11 전체를 다루되, 각 기술이 등장하는 맥락과 이유를 스토리텔링으로 전달하는 것이 핵심.

## 의도 밖 범위
- Docker/PostgreSQL 세팅 상세 (간략 안내만)
- Langfuse/모니터링 상세 (존재만 언급)
- CSS/Jinja2 프론트엔드 UI 구현 (API 중심)

## 차별점
1. **하나의 프로젝트, 처음부터 끝까지** — CH01에서 CH11까지 점진적 성장
2. **실패부터 시작** — 환각 → RAG 필요성 같은 체험에서 출발
3. **RAG 튜닝까지** — 10가지 튜닝 + 평가 프레임워크
4. **이야기로 읽는 기술서** — 비유·시나리오로 개념 풀이

## 형식 표준 (v2 신규)

### 언어·코드 컨벤션
- 주 언어: **Python 3.12**
- 보조: bash·yaml·dockerfile
- TODO 주석: `# TODO: ~합니다`
- 단계 번호: `# 1.` `# 2.` 의무
- 종결어미: 본문은 `~합니다`/`~입니다`. 단계 주석 명사구 예외

### "이것만은 기억하자"
- **반드시 `:::remember` directive** (마크다운 H2 평문 금지)
- 항목 3~5개 + "다음 챕터에서는" 한 줄 예고
- 마지막 챕터(CH11)는 책 전체 N챕터 회수 + "책을 덮으며" 단락

### 다이어그램 빈도·종류
- 실습 1개당 흐름 다이어그램 최소 1개
- 카탈로그 우선 컴포넌트:
  - `.terminal-log` — 실행 결과·서버 로그
  - `.pipeline-box` + `.pipeline-flow` + `.step-card` — RAG 파이프라인 3단계
  - `.scene-actors` — 사서 비유 등 다중 행위자
  - `.dual-path-compare` — LLM 단독 vs RAG 분기
  - `.sp-figure` + `.sp-flow` + `.sp-step` + `.sp-row` + `.sp-compare` + `.sp-chip` — 범용 sp-* 시리즈
  - `.arch-fullmap` (중간 챕터 책 구성도) · `.arch11` (CH11 최종 구성도 전용)
- 인라인 `style="..."` 0건 · hex 색 직접 박힘 0건
- 색 토큰: Primary(`--color-accent`) · Secondary(`--color-accent-warm`) · Info(`--color-info`)만. Utility 신규 사용 금지

### 캐릭터 삼각 구도
- 주인공 **오픈이** (실행자, 신입사원)
- **팀장** (힌트 제공자, 소크라테스식 질문)
- **동료** (문제 제기자, 실사용 피드백)
- 모든 대화 존댓말 통일
