그림 3-3 — 시스템 아키텍처 4안 (가로)

동일 시스템(사내 문서 인제스트 파이프라인)을 네 가지 아키텍처 다이어그램 스타일로. 흐름도가 아닌 컴포넌트·계층·관계 중심.

안 A. Layered Architecture

LAYERED

4계층(Input · Parsing · Processing · Storage)을 가로로 배치. 각 계층 박스 안에 컴포넌트가 들어 있고, 계층 사이는 화살표로 연결. 시스템의 책임 분리가 한눈에.

장점책임 분리(Layered)가 가장 명확. 시스템 다이어그램의 정석. 각 계층 안 컴포넌트 추가/교체가 시각적으로 쉬움.
단점4계층 가로 배치라 좁은 폭에서 글씨가 작아짐. 계층 라벨 영문 약어 의존.

안 B. Hub & Spoke (Router 중심)

HUB

중앙에 Format Router(허브)를 두고 좌측 입력, 우측으로 Markdown→청킹→DB 파이프라인. 라우팅 책임이 시각적으로 분리되어 "왜 분기되는지"가 즉시 보임.

단점전통적인 좌→우 단일 흐름이 약간 깨짐(허브 안에 파서가 들어 있어 시선이 두 번 이동).

안 C. System Boundary (외부·내부 경계)

BOUNDARY

좌측 외부 데이터 소스 / 가운데 시스템 경계 박스(INGESTION SYSTEM) / 우측 외부 저장소. C4·UML 컨텍스트 다이어그램 스타일. 시스템과 외부의 경계가 가장 명확.

장점C4 모델 컨텍스트 다이어그램의 정석. "시스템 vs 외부"가 가장 명확. 인제스트 시스템의 경계가 책 전체에서 일관되게 재사용 가능.
단점구조가 가장 빽빽함. 본문 폭에서 모듈 카드가 좁아질 수 있음. 영문 라벨 비중이 큼.

안 D. System Boundary + 1:1 Parser Mapping

D = C-CSS × D-FLOW

C안의 시스템 경계 디자인을 그대로 두고, 흐름은 D안처럼 PDF→PDF Parser, DOCX→DOCX Parser, XLSX→XLSX Parser의 1:1 매핑을 시각적으로 정렬. 외부 3개 카드와 시스템 안 3개 파서 모듈이 같은 행에 위치.

장점C안의 정돈된 시스템 경계 + D안의 1:1 파서 매핑 메시지. 외부 카드와 파서 모듈이 같은 행에 위치해 PDF→PDF Parser 매핑이 시각적으로 자연스럽게 읽힘. 순수 HTML/CSS — Mermaid 의존성 없음.
